ডিভাইসের ভূমিকা চেনা

ডায়াগ্রাম দেখে চিনতে হবে: router, Layer 2 switch, Layer 3 switch, firewall, access point, WLC (wireless controller), endpoint, server, PoE device।

🔀 Layer 2 vs Layer 3 switch L2 switch: শুধু MAC দেখে ফ্রেম সুইচ করে, VLAN-এর মধ্যে রাউটিং করতে পারে না। L3 switch: সুইচিং + রাউটিং দুটোই — SVI (Switched Virtual Interface) দিয়ে VLAN-এর মধ্যে রাউটিং করে। ক্যাম্পাস নেটওয়ার্কে inter-VLAN routing-এর আধুনিক উপায় এটাই।

🧠 যাচাই করুন
Interface "up/down" মানে কী?

প্রথম "up" = physical স্তর ঠিক (সিগন্যাল আছে), দ্বিতীয় "down" = data link স্তরে সমস্যা (line protocol down) — যেমন encapsulation mismatch বা keepalive ব্যর্থ।

VLAN আর IP subnet কি একই জিনিস?

না। VLAN হলো Layer 2 broadcast domain; subnet হলো Layer 3 ঠিকানার সীমা। সাধারণত একটার সাথে একটা মেলানো হয়, কিন্তু ধারণাগতভাবে আলাদা। এটা পরীক্ষার প্রিয় প্রশ্ন।

🔑 সূত্র মনে রাখুন Block size = 256 − মাস্কের মান। যেমন /26 → মাস্ক 192 → block = 256−192 = 64।

সাবনেটগুলো block size-এর গুণিতকে বসে: /26-এ 0, 64, 128, 192।

তিন ধাপে যেকোনো প্রশ্ন সমাধান

🎯 প্রশ্ন: 172.16.45.170/27 — network, broadcast, রেঞ্জ? ধাপ ১ — block size: /27 → মাস্ক 224 → block = 256−224 = 32
ধাপ ২ — কোন সাবনেটে? ৩২-এর গুণিতক: 0, 32, 64, 96, 128, 160, 192, 224। ১৭০ পড়ে ১৬০ আর ১৯২-এর মাঝে → network = 172.16.45.160
ধাপ ৩ — বাকিটা: Broadcast = পরের সাবনেটের ঠিক আগে = 172.16.45.191। ব্যবহারযোগ্য = .161 থেকে .190

VLSM — ভিন্ন আকারের সাবনেট

বাস্তবে প্রতিটা LAN-এর আকার আলাদা। VLSM-এ নিয়ম একটাই: সবচেয়ে বড় প্রয়োজন আগে বরাদ্দ করুন, তারপর ছোটগুলো।

🎯 উদাহরণ: 192.168.1.0/24 ভাগ করুন প্রয়োজন: LAN-A ৫০ হোস্ট, LAN-B ২৫ হোস্ট, LAN-C ১০ হোস্ট, দুটো WAN লিংক (২ করে)।

বড় থেকে ছোট:
LAN-A (৫০) → দরকার ৬২ → /26 → 192.168.1.0/26 (.0–.63)
LAN-B (২৫) → দরকার ৩০ → /27 → 192.168.1.64/27 (.64–.95)
LAN-C (১০) → দরকার ১৪ → /28 → 192.168.1.96/28 (.96–.111)
WAN-1 (২) → /30 → 192.168.1.112/30 (.112–.115)
WAN-2 (২) → /30 → 192.168.1.116/30 (.116–.119)
🚫 ফাঁদ — ছোট আগে বরাদ্দ করা ছোট সাবনেট আগে দিলে বড়টার জন্য সঠিক সীমানায় জায়গা নাও থাকতে পারে (সাবনেট সবসময় block size-এর গুণিতকে শুরু হতে হয়)। তাই সবসময় বড় থেকে ছোট।

🧠 দ্রুত অনুশীলন
10.1.1.100/26 — network address?

Block = 64। গুণিতক: 0, 64, 128। ১০০ পড়ে ৬৪–১২৭-এ → network = 10.1.1.64, broadcast = 10.1.1.127, রেঞ্জ .65–.126।

৩০০ হোস্টের জন্য কোন মাস্ক?

২⁸−২=২৫৪ যথেষ্ট নয়; ২⁹−২=৫১০ যথেষ্ট। তাই ৯ হোস্ট বিট → /23 (255.255.254.0)।

FE80::1 কী ধরনের অ্যাড্রেস?

Link-local — শুধু ওই লিংকে বৈধ, রাউট হয় না। প্রতিটা IPv6 ইন্টারফেসে স্বয়ংক্রিয়ভাবে একটা থাকে।

VLAN হলো একটা সুইচকে যৌক্তিকভাবে কয়েকটা আলাদা সুইচে ভাগ করা। প্রতিটা VLAN একটা আলাদা broadcast domain।

🏢 উপমা — একই ফ্লোরে পার্টিশন একটা বড় হলঘরে পার্টিশন দিয়ে আলাদা কক্ষ বানালেন। শারীরিকভাবে এক ফ্লোর, কিন্তু এক কক্ষের কথা অন্য কক্ষে যায় না। VLAN ঠিক তাই — এক সুইচ, কিন্তু আলাদা যৌক্তিক নেটওয়ার্ক।

Trunk — একাধিক VLAN এক লিংকে

দুটো সুইচের মধ্যে প্রতিটা VLAN-এর জন্য আলাদা কেবল টানা অবাস্তব। Trunk একটা লিংকেই সব VLAN বহন করে — প্রতিটা ফ্রেমে 802.1Q tag লাগিয়ে (৪ byte, VLAN ID সহ) চেনা যায় কোন ফ্রেম কোন VLAN-এর।

! trunk কনফিগার
Switch(config)# interface gi0/24
Switch(config-if)# switchport trunk encapsulation dot1q   ! কিছু মডেলে লাগে
Switch(config-if)# switchport mode trunk
Switch(config-if)# switchport trunk allowed vlan 10,20,30
Switch(config-if)# switchport trunk native vlan 99

! যাচাই
Switch# show interfaces trunk
🚫 Native VLAN — পরীক্ষার প্রিয় ফাঁদ Native VLAN-এর ফ্রেম trunk-এ tag ছাড়া যায় (ডিফল্ট VLAN 1)। দুই প্রান্তে native VLAN আলাদা হলে VLAN leaking হয় — এক VLAN-এর ট্রাফিক অন্য VLAN-এ চলে যায়, আর CDP native VLAN mismatch সতর্কতা দেয়।

নিরাপত্তা অনুশীলন: native VLAN বদলে একটা অব্যবহৃত VLAN-এ (যেমন 99) নিয়ে যান, আর VLAN 1 ব্যবহার করবেন না। এটা VLAN hopping আক্রমণ ঠেকায়।

Inter-VLAN Routing — তিনটা উপায়

VLAN গুলো আলাদা broadcast domain, তাই তাদের মধ্যে যোগাযোগে রাউটিং লাগে। তিনটা পদ্ধতি:

১. Router-on-a-stick (সাব-ইন্টারফেস)

! রাউটারে একটাই ফিজিক্যাল ইন্টারফেস, কয়েকটা সাব-ইন্টারফেস
Router(config)# interface gi0/0
Router(config-if)# no shutdown
Router(config)# interface gi0/0.10
Router(config-subif)# encapsulation dot1q 10
Router(config-subif)# ip address 192.168.10.1 255.255.255.0
Router(config)# interface gi0/0.20
Router(config-subif)# encapsulation dot1q 20
Router(config-subif)# ip address 192.168.20.1 255.255.255.0
🚫 ভুলে যাওয়া ধাপ সাব-ইন্টারফেস কাজ করবে না যদি: (১) ফিজিক্যাল ইন্টারফেসে no shutdown না দেন, (২) সুইচের দিকের পোর্ট trunk না হয়, (৩) encapsulation dot1q-এ ভুল VLAN নম্বর দেন।

২. SVI (Layer 3 switch) — আধুনিক উপায়

Switch(config)# ip routing                    ! এটা না দিলে রাউটিং হবে না!
Switch(config)# interface vlan 10
Switch(config-if)# ip address 192.168.10.1 255.255.255.0
Switch(config-if)# no shutdown
Switch(config)# interface vlan 20
Switch(config-if)# ip address 192.168.20.1 255.255.255.0
Switch(config-if)# no shutdown
🚫 ip routing ভুলে যাওয়া L3 সুইচে SVI বানালেন, IP দিলেন, কিন্তু ip routing দিলেন না — তাহলে VLAN-এর মধ্যে রাউটিং হবে না। পরীক্ষার সিমুলেশনে এটা খুব সাধারণ ফাঁদ।

৩. প্রতি VLAN-এ আলাদা রাউটার পোর্ট

সহজ কিন্তু অপচয়ী — প্রতিটা VLAN-এর জন্য একটা ফিজিক্যাল পোর্ট। বাস্তবে কম ব্যবহৃত।

🧠 যাচাই করুন
Trunk-এ native VLAN-এর ফ্রেম কীভাবে যায়?

Tag ছাড়া (untagged)। এজন্যই দুই প্রান্তে native VLAN মিলতে হবে, নাহলে ট্রাফিক ভুল VLAN-এ চলে যাবে।

Router-on-a-stick-এ সুইচের পোর্ট কী মোডে?

Trunk — কারণ রাউটারকে সব VLAN-এর ট্যাগসহ ট্রাফিক পাঠাতে হবে।

STP ও EtherChannel

domain-2b

সুইচড নেটওয়ার্কে redundancy দরকার, কিন্তু redundancy মানেই লুপ — আর Layer 2-তে লুপ মারাত্মক। STP এই সমস্যা সমাধান করে।

💥 লুপ কেন এত বিপজ্জনক? IP header-এ TTL আছে, কিন্তু Ethernet frame-এ TTL নেই। তাই লুপে পড়া ফ্রেম চিরকাল ঘুরতে থাকে। একটা broadcast ফ্রেম লুপে পড়লে broadcast storm হয় — সেকেন্ডের মধ্যে পুরো নেটওয়ার্ক অচল। সাথে MAC টেবিল অস্থির হয়ে যায় (MAC flapping)।

STP কীভাবে কাজ করে

মূল ধারণা: redundant পথ রাখো, কিন্তু যৌক্তিকভাবে কিছু পোর্ট ব্লক করে লুপ-মুক্ত একটা গাছ (tree) বানাও। মূল লিংক ব্যর্থ হলে ব্লক করা পোর্ট চালু হয়ে যায়।

ধাপ ১ — Root Bridge নির্বাচন

সবচেয়ে কম Bridge ID যার, সে root। Bridge ID = Priority (৪ বিট, ডিফল্ট 32768) + MAC অ্যাড্রেস। Priority সমান হলে সবচেয়ে ছোট MAC জেতে।

🎯 Priority-র নিয়ম Priority বাড়ে ৪০৯৬-এর গুণিতকে (0, 4096, 8192, ..., 61440)। তাই root ঠিক করতে: spanning-tree vlan 10 priority 4096। অথবা সহজ উপায়: spanning-tree vlan 10 root primary

EtherChannel — একাধিক লিংক এক করা

🧠 যাচাই করুন
দুটো সুইচে priority সমান হলে root কে হবে?

যার MAC অ্যাড্রেস সবচেয়ে ছোট। Bridge ID = priority + MAC, তাই priority সমান হলে MAC টাই-ব্রেকার।

LACP-তে দুই পাশেই passive দিলে?

EtherChannel তৈরি হবে না — কেউ আলোচনা শুরু করছে না। অন্তত একপাশে active লাগবে।

Ethernet frame-এ TTL না থাকার পরিণতি?

লুপে পড়া ফ্রেম চিরকাল ঘুরবে → broadcast storm। এজন্যই Layer 2-তে STP অপরিহার্য।

পথ বাছাইয়ের ক্রম — অত্যন্ত জরুরি

🎯 রাউটার তিন ধাপে সিদ্ধান্ত নেয় ১. Longest Prefix Match — সবচেয়ে নির্দিষ্ট রুট জেতে। /30 সবসময় /24-কে হারায়, AD বা metric যাই হোক।
২. AD — prefix দৈর্ঘ্য সমান হলে, কম AD জেতে।
৩. Metric — AD-ও সমান হলে (একই প্রোটোকল), কম metric জেতে।
🚫 সবচেয়ে বড় ফাঁদ অনেকে ভাবে "OSPF-এর AD 110, static-এর 1, তাই static সবসময় জেতে"। ভুল! যদি OSPF-এ 10.1.1.0/26 থাকে আর static-এ 10.1.1.0/24, তাহলে /26-এর মধ্যে পড়া গন্তব্যের জন্য OSPF জিতবে — কারণ longest prefix match আগে দেখা হয়, AD পরে।

Static Route কনফিগার

! মূল গঠন: ip route [গন্তব্য] [মাস্ক] [next-hop অথবা exit-interface]

! ১. Next-hop দিয়ে (সুপারিশকৃত)
Router(config)# ip route 192.168.5.0 255.255.255.0 10.1.1.254

! ২. Exit interface দিয়ে (point-to-point লিংকে)
Router(config)# ip route 192.168.5.0 255.255.255.0 serial 0/0/0

! ৩. Default route — "বাকি সব এদিকে"
Router(config)# ip route 0.0.0.0 0.0.0.0 203.0.113.1

! ৪. Floating static — ব্যাকআপ পথ (AD বাড়িয়ে দিলাম)
Router(config)# ip route 192.168.5.0 255.255.255.0 10.1.1.253 200
🎯 Floating static route শেষে একটা সংখ্যা (AD) দিলে সেটা "ভাসমান" ব্যাকআপ হয়ে যায়। উপরের উদাহরণে AD=200, যা OSPF-এর 110-এর চেয়ে বেশি — তাই সাধারণ অবস্থায় OSPF-এর রুট ব্যবহার হবে। OSPF রুট হারিয়ে গেলে তবেই এই static রুট টেবিলে ঢুকবে। পরীক্ষায় "ব্যাকআপ পথ কীভাবে বানাবেন" প্রশ্নের উত্তর এটাই।

🧠 যাচাই করুন
Static (AD 1) আর OSPF (AD 110) — OSPF-এর prefix বেশি নির্দিষ্ট হলে কে জেতে?

OSPF। Longest prefix match সবার আগে দেখা হয়; AD শুধু একই দৈর্ঘ্যের prefix-এর মধ্যে তুলনার জন্য।

Floating static route কী?

ইচ্ছাকৃতভাবে বেশি AD দেওয়া static route, যা শুধু প্রধান পথ ব্যর্থ হলে সক্রিয় হয় — ব্যাকআপ হিসেবে কাজ করে।

OSPF — Single Area

domain-3b

CCNA-তে শুধু single-area OSPFv2 লাগে। OSPF একটা link-state প্রোটোকল — প্রতিটা রাউটার পুরো টপোলজির মানচিত্র বানিয়ে নিজে সেরা পথ হিসাব করে (Dijkstra অ্যালগরিদম)।

Neighbor সম্পর্ক তৈরি

OSPF রাউটাররা 224.0.0.5 multicast-এ Hello প্যাকেট পাঠিয়ে প্রতিবেশী খোঁজে। কিন্তু প্রতিবেশী হতে কিছু জিনিস অবশ্যই মিলতে হবে।

🎯 Neighbor হওয়ার শর্ত — মুখস্থ করুন ১. Area ID একই হতে হবে
২. Hello ও Dead interval মিলতে হবে (ডিফল্ট 10/40 সেকেন্ড broadcast-এ)
৩. Subnet একই হতে হবে (একই নেটওয়ার্কে থাকতে হবে)
৪. Authentication মিলতে হবে (থাকলে)
৫. MTU মিলতে হবে
৬. Router ID অবশ্যই আলাদা হতে হবে
৭. Stub area flag মিলতে হবে

পরীক্ষায় "OSPF neighbor হচ্ছে না কেন?" — এই তালিকা ধরে মেলান।

Router ID কীভাবে ঠিক হয়

অগ্রাধিকার ক্রমে: (১) router-id কমান্ডে দেওয়া মান → (২) সবচেয়ে বড় loopback ইন্টারফেসের IP → (৩) সবচেয়ে বড় সক্রিয় ফিজিক্যাল ইন্টারফেসের IP।

💡 Loopback কেন ব্যবহার করবেন? ফিজিক্যাল ইন্টারফেস বন্ধ হলে router ID বদলে যেতে পারে, যা OSPF অস্থিরতা তৈরি করে। Loopback ইন্টারফেস কখনো down হয় না — তাই স্থিতিশীল router ID-র জন্য loopback আদর্শ।

DR ও BDR

Broadcast/multi-access নেটওয়ার্কে (যেমন Ethernet) প্রতিটা রাউটার সবার সাথে সম্পর্ক তৈরি করলে অনেক বেশি ট্রাফিক হয়। তাই একটা DR (Designated Router) ও BDR বাছাই হয় — বাকিরা শুধু DR/BDR-এর সাথে কথা বলে।

🎯 DR/BDR নির্বাচন ১. সবচেয়ে বেশি OSPF interface priority (ডিফল্ট ১; 0 দিলে কখনো DR হবে না)
২. টাই হলে সবচেয়ে বড় Router ID
গুরুত্বপূর্ণ: নির্বাচন preemptive নয় — নতুন ভালো রাউটার এলেও বর্তমান DR বহাল থাকে যতক্ষণ না সে ব্যর্থ হয়।
Point-to-point লিংকে DR/BDR হয় না।

Controller-based networking

ঐতিহ্যবাহী নেটওয়ার্কে প্রতিটা ডিভাইস নিজেই সিদ্ধান্ত নেয়। SDN-এ control plane আলাদা করে একটা কেন্দ্রীয় controller-এ নেওয়া হয়।

🧭 তিনটা plane Data plane: আসল প্যাকেট ফরোয়ার্ড করা (দ্রুত, হার্ডওয়্যার)।
Control plane: সিদ্ধান্ত নেওয়া — routing protocol, STP (মস্তিষ্ক)।
Management plane: কনফিগার ও পর্যবেক্ষণ — SSH, SNMP।
🎯 Northbound vs Southbound API Northbound — controller থেকে উপরে অ্যাপ্লিকেশনের দিকে (সাধারণত REST API)। "আমি কী চাই" বলার পথ।
Southbound — controller থেকে নিচে ডিভাইসের দিকে (NETCONF, OpenFlow)। "ডিভাইসে কীভাবে করা হবে"।
মনে রাখুন: উত্তর = উপরে (অ্যাপ), দক্ষিণ = নিচে (ডিভাইস)।
